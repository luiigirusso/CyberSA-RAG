\section{Detailed analysis of the state of the art}
Knowledge graphs for cybersecurity offer holistic approaches to processing vast volumes of complex cybersecurity data from diverse sources. These tools can support security analysts in gaining detailed insights into cyber threats, enhancing cyber-situation awareness, acquiring new knowledge, and understanding correlations between aggregated data.

Additionally, they enable the visualization of networks, data flows, and attack paths, facilitating threat comprehension and prevention. By aggregating and integrating heterogeneous data and structuring its representation, it is possible to enhance situation awareness, allowing real-time threat monitoring and the anticipation of potential risk scenarios.

In \cite{sikos2023cybersecurity}, the most relevant graph-based data models used in this field are examined. Many cybersecurity and network-related features need to be stored, and the semantics of captured knowledge vary significantly depending on the graph data model used.

The real-time analysis of cybersecurity reports is a critical challenge for security experts, as an immeasurable amount of digital information is generated daily, requiring automated information extraction tools to facilitate data querying and retrieval.

In \cite{sarhan2021open}, Open-CyKG is introduced: an Open Cyber Threat Intelligence (CTI) Knowledge Graph (KG) framework built using an attention-based Open Information Extraction (OIE) neural model to extract valuable threat intelligence from unstructured Advanced Persistent Threat (APT) reports.

Specifically, relevant entities are first identified by developing a neural Named Entity Recognizer (NER) for cybersecurity, which helps label the triples generated by the OIE model. Then, the extracted structured data is canonicalized to construct the KG using fusion techniques with word embeddings. As a result, security professionals can execute queries to retrieve valuable insights from the Open-CyKG framework.

Afzaliseresht et al. \cite{afzaliseresht2020investigating} report that integrating natural language processing with knowledge graphs improves analysts' perception of environmental elements, while Najafi et al. \cite{najafi2019malrank} show that a SIEM-based graph using a MalRank algorithm achieves a 96\% detection rate for malicious entities.
Narayanan et al. \cite{narayanan2018cognitive} demonstrate that combining extended cybersecurity ontologies with sensor and textual data enables early event detection and the generation of actionable intelligence.
Other papers describe systems that offer a unified representation of network assets and threat data or that enhance query performance using domain-specific query languages, as with Noel et al. \cite{noel2018mission} and Sills et al. \cite{sills2020cybersecurity}, the latter attaining a 31\% increase in mean average precision for information retrieval tasks.
Approaches range from property graphs and graph embeddings to neural entity extraction and reinforcement learning. Collectively, these studies indicate that knowledge graph–enabled query systems can deliver a comprehensive, integrated view of cybersecurity information that supports improved threat prioritization and situational analysis by security analysts.

\subsubsection{Case study 1: Network structure}
The first case study represents a type of query that focuses on analyzing the network structure. This type of query is particularly useful for understanding the distribution of critical network services and assessing potential vulnerabilities or misconfigurations. Specifically, it aims to identify the presence of NTP or DNS services within different subnets.
\lstdefinelanguage{Cypher}{
  morekeywords={MATCH, RETURN, DISTINCT, UNION, WHERE, CONTAINS, OR},
  sensitive=true,
  basicstyle=\ttfamily\fontsize{8}{9}\selectfont, 
  morecomment=[l]{//},
  morestring=[b]"
}
\begin{lstlisting}[language=Python, caption=Case Study 1: Natural Language Query, label=lst:natural1]
"Are there DNS, NTP, or other UDP-based services in LAN 1?"
\end{lstlisting}


\begin{lstlisting}[language=Cypher, caption=Case Study 1: Cypher Query, label=lst:cypher1]
MATCH (s:ns0_Network {rdfs_label: "LAN 1"})-[p:ns1_contains]->(o)
WHERE tolower(o.uri) CONTAINS "dns" OR tolower(o.uri) CONTAINS "ntp"
RETURN s.uri AS subject, type(p) AS predicate, o.uri AS object
\end{lstlisting}


\subsubsection{Case study 2: Description of a specific attack technique}
This case of study focuses on retrieving information about a specific cyberattack technique.In this case, the query aims to obtain a detailed explanation of how a Reflection Amplification Attack works.
\begin{lstlisting}[language=Python, caption=Case Study 2: Natural Language Query, label=lst:natural2]
"Can you explain how a Reflection amplification attack works?"
\end{lstlisting}

\begin{lstlisting}[language=Cypher, caption=Case Study 2: Cypher Query, label=lst:cypher2]
MATCH (ap:ns2__AttackPattern)
WHERE tolower(ap.rdfs__label) CONTAINS "amplification" 
RETURN ap.uri AS subject, "description" AS predicate, ap.ns2__description 
AS object
\end{lstlisting}

\subsubsection{Case study 3: Detection of a specific attack technique}
The third case of study focuses on detecting a specific cyberattack technique based on the description of an observed scenario. The goal is to identify potential threats by analyzing network behaviors and correlating them with known attack techniques. 
In this example, the natural language query describes a situation where a large number of incoming UDP packets are detected, with the "ANY" argument being used. 
To answer this question, the system should retrieve two basic types of information:
\begin{enumerate}
    \item \textbf{DataComponents} – These elements represent observable artifacts in the network that can be used for attack detection (e.g., unusual traffic patterns, specific packet attributes).
    \item \textbf{AttackPatterns} – These nodes represent known attack techniques, which can be correlated with the detected DataComponents to infer possible threats.
\end{enumerate}
The corresponding Cypher (Listing~\ref{lst:cypher3}) query extracts all relevant DataComponents and AttackPatterns from the knowledge graph, allowing security analysts to establish a link between observed network anomalies and potential attack techniques.

This case study evaluates the system’s ability to map unstructured network observations to structured threat intelligence, demonstrating its usefulness in cyber threat detection and response scenarios.

\begin{lstlisting}[language=Python, caption==Case Study 3: Natural Language Query, label=lst:natural3]
"I detected many incoming UDP packets to my network that have 'ANY' 
as an argument. What might this be due to?"
\end{lstlisting}

\begin{lstlisting}[language=Cypher, caption=Case Study 3: Cypher Query, label=lst:cypher3]
MATCH (dc:ns2__DataComponent)
RETURN DISTINCT dc.uri AS uri
UNION
MATCH (ap:ns2__AttackPattern)
RETURN DISTINCT ap.uri AS uri
\end{lstlisting}

\subsubsection{Case study 4: Mitigation of a specific attack technique}
This final case study focuses on identifying mitigation strategies for a specific cyberattack technique. In particular, the query aims to retrieve effective countermeasures against Reflection Amplification Attacks.

The natural language query (Listing~\ref{lst:natural4})asks for ways to mitigate this attack, prompting the system to retrieve relevant information from the knowledge graph. The Cypher query (Listing~\ref{lst:cypher4}) searches for entities linked to attack mitigation strategies, specifically targeting attack patterns that contain the term "amplification" in their labels.
\begin{lstlisting}[language=Python, caption=Case Study 4: Natural Language Query, label=lst:natural4]
"How can I mitigate a Reflection amplification attack?"
\end{lstlisting}

\begin{lstlisting}[language=Cypher, caption=Case Study 4: Cypher Query, label=lst:cypher4]
MATCH (s)-[p:`ns2__mitigates`]->(o)
WHERE tolower(o.rdfs__label) CONTAINS "amplification"
RETURN s.uri AS subject, type(p) AS predicate, o.uri AS object
UNION
MATCH (s)-[p:`ns2__mitigates`]->(o)
WHERE tolower(o.rdfs__label) CONTAINS "amplification"
RETURN s.uri AS subject, "description" AS predicate, s.ns2__description AS object
\end{lstlisting}

\section{Description of the data and/or case study used for experimentation}

For the experimentation, a set of test scenarios has been defined to evaluate the system's performance in different contexts. The test queries are categorized into four distinct types:

\begin{itemize}
    \item \textbf{Network structure}: Queries related to the topology and organization of the network.
    \item \textbf{Description of a specific attack technique}: Queries aimed at retrieving detailed information about a given attack method.
    \item \textbf{Detection of a specific attack technique}: Queries focused on identifying the presence of an attack within the network.
    \item \textbf{Mitigation of a specific attack technique}: Queries concerning possible countermeasures to prevent or respond to an attack.
\end{itemize}

For each scenario, three distinct queries will be formulated and tested. This structured approach ensures a comprehensive evaluation of the system's performance across different conditions. By considering multiple queries per scenario, the results obtained will provide a more robust and representative assessment of the overall effectiveness and applicability of the proposed method.
